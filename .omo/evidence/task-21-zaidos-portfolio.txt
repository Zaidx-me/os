Design decisions / plan conformance
-----------------------------------
- The plan requires a "Download PDF" control whose behavior switches on
  whether a real PDF exists. That truth lives in the data layer
  (resumePdfUrl), NEVER in a runtime probe: HEAD/fetching a missing
  public/ asset would log a 404 console error and fail the
  no-console-errors e2e gate, and a fake PDF must never be shipped. With
  resumePdfUrl null the control is a button that calls window.print();
  the stylesheet makes print output the polished PDF.
- Prop-less component: the first implementation passed props (title, icon)
  into ResumeApp and hit the WindowAppComponent registry type error (the
  registry types all windows as { title: string; icon: IconName }, so any
  window component must accept EXACTLY those props). ResumeApp takes no
  props and reads everything from the content layer. This fixed the
  component-registry weak type.
- Naming/labels use the owner's data only; no invented copy. Period
  contract (— / Current) reused from ExperienceApp conventions.

Implementation notes
--------------------
- The resume is assembled at runtime from the content layer (single source
  of truth) — it is not a static document, so it can never drift from the
  About/Experience data. Print is the delivery mechanism; a future real
  PDF (owner-supplied) flips resumePdfUrl and the control becomes a
  download link.
- jsdom has no window.print; tests stub it explicitly (vi.spyOn +
  mockImplementation, restored in afterEach).
