Acceptance mapping (plan line 204)
----------------------------------
- Snap preview overlay: left half / right half / full glass panel, rendered
  through a portal (z-30) above the window; follows the pointer's zone.
- Drop -> mode=tile with exact bounds (gutter 8px; x=gap, y=waybar+gap,
  w=50%-gap/2 = vw/2-12); full = maximizeBounds (waybar + 8px gutter).
- Keyboard: Mod+Left/Right tile halves, Mod+Up tile full, Mod+F float toggle
  restores prior bounds, Mod+Shift+Left/Right move workspace via the
  moveWindowToWorkspace orchestrator (never a raw store action).
- Tile math uses the viewport-capped clamps from todo 12 (setBounds).
- Scope boundary respected: no auto-tiling on open, windows open floating and
  the user snaps; no Hyprland-style layouts implemented.

Design decisions / fixes found during verification
--------------------------------------------------
1. Top-edge drag now SNAPS FULL (y<40), changing task 13's "clamp at the
   waybar" behavior. The old clamp tests were reworked to drop at exactly
   y=WAYBAR_H=40 (outside the 40px band) so clamping is still covered in
   both unit and e2e.
2. Preview style MUST use explicit CSS prop names (left/top/width/height) —
   a style object with {x,y,w,h} keys is ignored by React (caught by a
   failing toHaveStyle unit test and fixed).
3. snap() records floatBounds only when currently floating, so re-snapping a
   tiled window preserves the original float position for Mod+F restore.
4. Desktop icons occupy the top-left (flex-col flex-wrap), so a left-snapped
   window covers the next app's icon — the side-by-side e2e snaps chess RIGHT
   first, opens terminal, then snaps terminal left.
