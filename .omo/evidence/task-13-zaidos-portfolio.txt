Acceptance mapping (plan line 195)
----------------------------------
- Titlebar = AppIcon + title + square rice-style min/max/close controls.
- Drag = manual pointer math (pointer capture + window-level pointermove/
  pointerup), viewport-clamped, NEVER above the waybar (dragBounds).
- 8 invisible resize handles (cursor styles), min 360x240 (resizeBounds).
- Motion: open scale 0.96->1 + fade 200ms, close reverse, focus z+highlight.
- Maximize fills workspace minus waybar + 8px gutter (e2e asserts 1424x844
  at the 1440x900 viewport), restore is lossless (float bounds untouched).
- Double-click title toggles maximize; dragging disabled while maximized.
- Close restores focus to the previous window (workspaces.closeWindow +
  wm.close promotion) — e2e + unit verified.
- Pointerdown anywhere focuses the window via focusWindow (both stores).
- Minimize = mounted + aria-hidden + visibility hidden (waybar task buttons
  land in todo 16).

Fixes found during verification
-------------------------------
1. Resize-handle overlay bug: the 8-handle layer was `absolute inset-0`, so it
   intercepted ALL titlebar clicks/drags (16 of 18 window e2e tests failed —
   only the SE-resize test passed). Fix: overlay is `pointer-events-none`, each
   handle is `pointer-events-auto` — hit-testing now only on the handle strips.
2. Launcher e2e flake (pre-existing, task 11 scope): the Mod+Space hotkey
   listener attaches in a React effect AFTER the desktop paints, so a one-shot
   keypress could land before wiring and the launcher never opened. Fixed with
   an openLauncher() retry-poll (press only while closed; a genuinely broken
   hotkey still fails). Verified stable across 2 consecutive full-spec runs.
