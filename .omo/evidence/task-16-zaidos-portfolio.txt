Design decisions / fixes found during verification
---------------------------------------------------
1. The killer e2e bug: "Mod+Tab lists windows topmost-first; arrows + Enter
   select" failed intermittently — Enter closed the switcher but the terminal
   never became focused. Root cause (proven by a throwaway e2e/_diag.spec.ts):
   after dblclick-opening a desktop icon, the ICON BUTTON retains DOM focus;
   pressing Enter keydowns that button FIRST, whose own onKeyDown handler calls
   open(app.id) — spawning a SECOND chess window on top — and only then bubbles
   to the window listener. Fix: the switcher's keydown listener runs in the
   CAPTURE phase (addEventListener "keydown", handler, true) and calls
   preventDefault + stopPropagation while open, so no keystroke can leak to a
   focused element underneath the overlay.
2. useEffectEvent (React 19.2, stable) replaces the previous
   `onKeyDownRef.current = ...` "latest handler ref" pattern. The old pattern
   hit the new react-hooks v6 rule `react-hooks/refs` ("Cannot update ref
   during render" — a lint error). Effect Event + capture-phase listener reads
   freshest open/entries/safeActive without a ref written during render; lint
   and e2e both pass.
3. WorkspaceView subscribes to ONLY minimized flags (useShallow over wm store),
   not the whole wm store, so dragging/resizing a window (geometry churn) does
   not re-render the window list on every frame.
4. Minimize now UNMOUNTS the window (it left the workspace layer entirely) —
   previously it stayed mounted with aria-hidden. The AnimatePresence exit
   animation still plays; the waybar task is the window's only representation
   while minimized (toHaveCount(0) in both window.spec.ts and taskbar.spec.ts).
5. Switcher auto-dismiss adjusts state during render (`if (open && entries.length
   === 0) setOpen(false)`) rather than in an effect — avoids a cascading
   setState-in-effect (react-hooks v6 rule `react-hooks/set-state-in-effect`).
