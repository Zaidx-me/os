Design decisions / fixes found during verification
--------------------------------------------------
1. React 19 (19.2.8) `lazy()` returns an OBJECT tagged
   `$$typeof: Symbol.for("react.lazy")` — NOT a function. The registry test
   asserts the symbol, not `typeof === "function"` (which was the initial
   failing assertion: 1 failed -> fixed -> 191 passed).
2. The old placeholder content (`<div data-testid="ws-window">` + "No window
   content yet") is replaced by WindowHost. e2e for EVERY app asserts both
   window-<appId> (frame) and app-content-<appId> (lazy body) so the content
   provider is exercised, not just the frame.
3. openApp stays permissive for unknown ids (humanized title + default
   size) so wm.test.ts's "files" window and any launcher command still work —
   strictness lives in WindowHost (throws), not the store.
4. e2e uses the deterministic result row: fill launcher-input then click
   data-testid="launcher-result-<appId>" (Launcher.tsx:282) — NOT a
   non-existent "launcher-results" testid (initial apps.spec asserted it and
   all 24 e2e tests failed with locator not-found; fixed by using the real
   launcher-list/launcher-result testids proven in launcher.spec.ts).
5. Terminal keeps defaultSize {w:640, h:480} (wm.test.ts pins openApp("terminal")
   geometry); defaults preserved exactly.
