Task 22 — Contact app + /api/contact
====================================
Date: 2026-08-11
Status: PASS

Files created
-------------
- src/app/api/contact/route.ts — POST /api/contact: lightweight validation
  (no zod — name/email/subject/message required, email regex), honeypot
  field (filled `website` short-circuits to a silent 200 {ok:true} without
  sending), in-memory rate limit (5 POSTs/min per IP via cf-connecting-ip,
  then 429 { error: "Too many messages" }), and an env-gated Resend relay:
  RESEND_API_KEY + CONTACT_TO_EMAIL (+ optional RESEND_FROM override)
  present -> Resend send with from/to/subject/replyTo/text; absent ->
  501 { message: "mailto" } telling the client to fall back to mailto.
  Resend SDK v6 non-throwing { data, error } contract; error -> 500.
  Logging (console.debug) never includes email addresses (PII-free).
- src/app/api/contact/route.test.ts — Vitest API tests (6): 501 when env
  keys missing; 400 for invalid payloads (empty fields, bad email); 200
  with Resend called when keys are set (stub env via vi.stubEnv + mock
  module); honeypot short-circuit (no send); 429 after 5/min per-IP
  (different IPs isolated); 500 on Resend error. vi.resetModules() per
  test isolates the module-scoped rate-limit Map.
- src/components/apps/ContactApp.tsx — form (name/email/subject/message)
  with client-side validation mirroring the API, honeypot `website` field
  (hidden via absolutely-positioned off-screen styling), on submit -> POST
  /api/contact; 200 -> success state; 501 or network abort -> mailto:
  fallback link with subject/body filled from the typed values; 429 ->
  rate-limit message with NO mailto. Beside the form: socials row
  (GitHub/LinkedIn/Linktree from socials.ts) and a "copy email" button
  (navigator.clipboard.writeText(site.contactEmail), "Copied" feedback).
- src/components/apps/ContactApp.test.tsx — Vitest (10): renders form
  fields + honeypot + socials + copy button; input typing updates state;
  invalid/empty submit shows field errors without fetch; success path
  (POST 200 -> success text; body contains website:""); mailto fallback on
  501 (link href starts mailto: + subject/body filled); mailto fallback on
  network abort; 429 -> rate-limit message and NO mailto; copy email
  writes site.contactEmail and shows "Copied".
- e2e/contact.spec.ts — Playwright x2 (desktop+mobile): acceptance test
  (form renders, submit valid -> success via intercepted route 200) + QA
  tests: happy (success message, email body includes website:""), failure
  501 (intercepted 501 -> mailto link present with subject/body),
  failure network abort (route abort -> mailto fallback), failure 429
  (intercepted 429 -> rate-limit message, no mailto). All /api/contact
  requests intercepted — never touches the real (env-gated) Resend path.
- .env.example — RESEND_API_KEY, CONTACT_TO_EMAIL, RESEND_FROM placeholders.
- .gitignore — added `!.env.example` exception (placeholder file tracked,
  `.env*` still ignored).

Implementation notes
--------------------
- fetch errors: `catch` on fetch itself (network abort) also maps to the
  mailto fallback — matches the plan's "network error" failure case.
- Rate limit state is module-scoped (works across requests in dev/prod);
  unit tests use vi.resetModules() + vi.stubEnv for isolation.
- mailto link subject/body are encodeURIComponent'd; e2e asserts the href
  prefix (mailto:...) and that encoded subject/body are present.
